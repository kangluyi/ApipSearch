# 最佳实践

## 启用缓存

对于高频访问的站点，强烈建议开启查询缓存。同一个 IP 在缓存有效期内不会重复请求数据源，可以显著降低 API 调用量和响应延迟。

```php
'cache_enabled' => true,
'cache_ttl' => 3600,  // 1 小时
```

## 合理设置超时

建议将超时时间设置在 3-5 秒之间。过短可能导致数据源来不及响应，过长会影响用户体验。

```php
'timeout' => 5,
```

## 数据源选择建议

| 场景 | 推荐数据源 | 原因 |
|------|-----------|------|
| 国内为主 | 高德地图 | 国内定位精度更高 |
| 海外为主 | 百度地图 | 覆盖面更广 |
| 混合场景 | 百度地图 | 综合表现稳定 |
| 自有数据 | 自定义源 | 无 API 调用费用 |

## 异常处理

在业务代码中做好降级处理，当 IP 定位服务不可用时，不应影响主流程：

```php
try {
    $result = ApipSearch::lookup($ip);
    $location = $result['country'] . $result['province'];
} catch (\Exception $e) {
    // 降级处理，使用默认值
    $location = '未知地区';
}
```

## 日志管理

建议开启查询日志，便于排查问题和分析访客分布。定期清理历史日志避免占用过多存储空间。

::: tip
如果你的站点访问量较大，建议将日志写入独立的日志文件或数据库表中，方便后续分析。
:::
